# Region Console

Приложение для Windows 8.1 (C# + WinForms, .NET Framework 4.7.2), предназначенное для сопровождения **ручной** смены региона на телевизорах Samsung и для раздачи интернета с ПК через Wi-Fi (точка доступа Windows + общий доступ к интернету ICS).

Собранный результат — `RegionConsole.exe`. Исходный код хранится в репозитории отдельно (см. директорию `RegionConsole/` и артефакт "исходный код" в GitHub Actions).

## ⚠️ Важное предупреждение

Вкладка «Терминал» — **только визуальная симуляция** в стиле фильмов про хакеров (поток строк, случайные числа, шестнадцатеричные коды, прогресс-бар).  
Приложение **не взламывает системы**, не подключается к телевизору и **не меняет регион телевизора автоматически**. Регион пользователь меняет вручную на самом телевизоре.

## Требования

- Операционная система: Windows 8.1 (также работает на более новых версиях Windows).
- .NET Framework 4.7.2 (или 4.8) установлен в системе.
- Права администратора необходимы для запуска/остановки точки доступа и настройки общего доступа к интернету (ICS).
- Wi-Fi-адаптер с поддержкой режима размещённой сети (hosted network) — для раздачи Wi-Fi.
- Для раздачи через VPN: активный VPN-адаптер и виртуальный адаптер точки доступа.

### Установка .NET Framework 4.7.2

Скачайте установщик с официального сайта Microsoft:

https://dotnet.microsoft.com/download/dotnet-framework/net472

Запустите установщик от имени администратора и следуйте инструкциям. После установки перезагрузка может не потребоваться.

## Запуск приложения

1. Скачайте собранный `RegionConsole.exe` (артефакт GitHub Actions или локальная сборка).
2. Запустите двойным кликом. Аутентификация администратора запрашивается **только при действиях с сетью** (запуск точки доступа, ICS); само приложение работает без повышения прав.
3. При первом сетевом действии приложение предложит перезапуститься от имени администратора — согласитесь.

## Вкладка «Терминал»

Кнопки:

- **Сканирование** — запускает визуальный поток сканирования (строки, MAC, SSID, каналы, progress).
- **Вычисления** — запускает поток вычислений (хэши, ключи, контрольные суммы).
- **Стоп** — останавливает все потоки симуляции.
- **Очистить** — очищает окно терминала.

Эффектный поток строк, случайных чисел, шестнадцатеричных кодов и прогресса реализован исключительно для визуального сопровождения. Никаких реальных действий с сетью или телевизором он не выполняет.

## Вкладка «Wi-Fi + VPN»

### Раздача Wi-Fi

1. Введите имя сети (SSID, до 32 символов) и пароль (8–63 символа, WPA2-PSK).
2. Нажмите **Запустить точку доступа** — выполнится `netsh wlan set hostednetwork` и `netsh wlan start hostednetwork`.
3. Результат команд Windows отображается в логе на той же вкладке.
4. **Остановить точку доступа** — выполняет `netsh wlan stop hostednetwork`.
5. **Обновить список** — показывает сетевые адаптеры через `netsh interface show interface`.

### Общий доступ к интернету (ICS)

1. Выберите **VPN-адаптер** как источник интернета.
2. Выберите **виртуальный адаптер точки доступа** как получателя (обычно появляется после запуска точки доступа, например «Подключение по локальной сети* N»).
3. Нажмите **Настроить общий доступ**. Перед изменением настроек появится диалог подтверждения.
4. Если общий доступ уже включён на другом адаптере, его замена требует явной галочки «Подтверждаю, что хочу заменить существующий общий доступ другого адаптера».
5. **Отключить общий доступ** — отключает ICS на выбранных адаптерах.

### Предупреждения и ограничения

- Работа точки доступа зависит от Wi-Fi-адаптера, его драйвера и поддержки режима hosted network. Не все адаптеры это поддерживают.
- **Прохождение трафика через VPN и отсутствие утечек не гарантируются.**
- Пароль точки доступа **никогда не сохраняется** и не пишется в журнал.
- После настройки проверьте внешний IP телевизора (например, на сайте 2ip.ru) с самого телевизора, чтобы убедиться, что трафик ходит через ожидаемый канал.
- Чтобы отключить общий доступ: используйте кнопку «Отключить общий доступ» либо снимите общий доступ в свойствах адаптера через Панель управления → Сетевые подключения.

## Сборка и GitHub Actions

В репозитории настроен рабочий процесс `.github/workflows/build.yml`:

- Собирает решение `RegionConsole.sln` в конфигурации Release под Windows (`windows-latest`, .NET Framework 4.7.2).
- Запускает автотесты (проверка валидаторов входящих данных).
- Публикует два отдельных артефакта:
  1. готовый `.exe` (`RegionConsole.exe`);
  2. архив исходного кода (`RegionConsole-source.zip`).
- Запуск возможен вручную через вкладку **Actions → Build Region Console → Run workflow** (`workflow_dispatch`), а также при пушах и pull-запросах в ветки `main` и `arena/**`.

Локальная сборка (требуется .NET SDK):

```bash
dotnet build RegionConsole.sln -c Release
dotnet test RegionConsole.sln -c Release
```

Готовый `.exe` появится в `RegionConsole\bin\Release\RegionConsole.exe` вместе с исходным изображением иконки `Resources\icon.png`. Иконка приложения (`Resources\region_console.ico`) встроена в `.exe`, окно и панель задач.

## Что проверено, а что требует проверки на реальном ПК

| Компонент | Статус |
|-----------|--------|
| Валидация SSID и пароля | Автотесты (MSTest) пройдены в CI |
| Запуск/остановка hosted network через netsh | Требует проверки на реальном Windows 8.1 с Wi-Fi-адаптером |
| Список сетевых адаптеров | Требует проверки на реальном оборудовании |
| ICS через NetSharingManager (COM) | Требует проверки на реальном оборудовании; поведение зависит от версии Windows и текущей конфигурации общего доступа |
| Интерфейс и симуляция терминала | Проверена разработчиком при сборке UI |
| Работа на Windows 8.1 | Требует проверки на реальном компьютере с Windows 8.1 |
